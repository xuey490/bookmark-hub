## 修复 systemd 203/EXEC（Permission denied）

- 用户服务器报错：`Failed to execute /opt/bookmark-hub/backend/.venv/bin/uvicorn: Permission denied` + `status=203/EXEC`。
- 根因：`root` 执行 `uv sync`，uv 把 Python 下载到 `/root/.local/share/uv/python/...`，而 `/root` 是 `700`，服务用户 `bookmark` 无法穿过目录去 exec shebang 解释器。注意 203/EXEC 是「连进程都没起来」，与 Python 代码无关。
- 修法一（改 unit）：`ExecStart` 从 `.venv/bin/uvicorn` 改为 `.venv/bin/python -m uvicorn ...` —— 不依赖脚本可执行位，也不依赖 shebang 解释器。
- 修法二（根治）：安装依赖时设 `UV_PYTHON_INSTALL_DIR=/opt/bookmark-hub/.uv-python`，把托管 Python 放进项目内；`.gitignore` 已加 `.uv-python/`。
- `deploy/install-service.sh` 重写：新增 `run_as_run_user()`（runuser，回退 su）+ `can_exec_as_run_user()`，写 unit 前以服务用户试 `test -x $(readlink -f .venv/bin/python)`，不可执行时打印权限链 `namei -l` 与三种修复方案后退出；另加 `run_as_run_user python -c "import uvicorn, fastapi"` 依赖校验、`chmod +x .venv/bin/*`、`chmod a+x` 路径各级目录、venv 缺失时自动创建。
- 关键教训：`UV_PYTHON_INSTALL_DIR` 不设时 uv 用 `~/.local/share/uv`，root 装依赖给非 root 服务用必然踩这个坑；`--python-preference only-managed` 不必要（默认就会优先托管版本），去掉更灵活。
- README「常驻服务」章节 + `docs/开发文档.md` 12.3 同步：新增「203/EXEC Permission denied 排查」小节（三种成因、`readlink -f` + `namei -l` 排查、三种修法）。
